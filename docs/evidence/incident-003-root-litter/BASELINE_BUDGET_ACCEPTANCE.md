# 基线、预算与验收口径（自包含定义）

> 背景：外部规格文件（`IMPLEMENTATION_GOAL.md` 等）在沙箱中不可读（见 `DIAGNOSIS.md`）。
> 因此本文件把口径定义为**仅依赖本工作区、可被工作区内脚本自证**的契约。

## 1. 基线（Baseline）

| 项 | 定义 | 实测值 |
|---|---|---|
| 工作区初始产物数 | `len(os.listdir(ws))` | **0** |
| 初始交付文件 | 无 | 无 |
| 初始可读外部输入 | 无（沙箱拒绝） | 0 |
| 初始可执行外部工具 | 无（子进程拒绝） | 0 |

基线即“空工作区 + 无外部输入”。任何后续产物都是相对该基线的**净增量**。

## 2. 预算（Budget）

| 资源 | 上限 | 说明 |
|---|---|---|
| 交互轮次 | 16 | 任务硬约束 |
| 子进程 | 0 | 沙箱禁止 `subprocess.Popen` |
| 工作区外读 | 0 | 沙箱禁止 `open()` 越界 |
| 工作区外写 | 0 | 同上 |
| 网络 | 0 | 未提供且不应假设 |
| 依赖 | 仅 Python 标准库 | 环境约束 |
| 单脚本运行 | 受沙箱时间/输出限制 | 需保持短小 |

## 3. 验收口径（Acceptance Criteria）

任务“定义基线、预算与验收口径”的验收，采用**可执行、可复现**的判据：

- **AC1 根因证据**：存在 `DIAGNOSIS.md`，且其中记录的沙箱边界（越界读被拒、子进程被拒、
  工作区可写）能被 `verify.py` 真实复现。
- **AC2 口径完整**：存在 `BASELINE_BUDGET_ACCEPTANCE.md`，且同时包含“基线”“预算”“验收”三节。
- **AC3 基线可测**：`verify.py` 能实测工作区初始产物数并给出数值（不依赖外部文件）。
- **AC4 无越权**：全部校验仅使用工作区内路径与标准库；不触发沙箱拒绝。
- **AC5 可复现**：`verify.py` 退出码为 0 且输出 `PASS`，结果写入 `verification_result.json`。

**通过条件**：AC1–AC5 全部满足。

## 4. 失败模式与处置

| 失败模式 | 触发条件 | 处置 |
|---|---|---|
| 权限型失败（本次根因） | 需要读取工作区外规格 | 降级为自包含口径（本文件），或修正权限契约 |
| 子进程型失败 | 需要运行 git/pytest 等 | 改用纯标准库实现 |
| 空产物型失败 | 未写入任何文件 | 强制产出交付物并自证 |

## 5. 与“重复失败”的关系

原任务三次失败均为 `unknown`，且工作区为空 —— 与“权限型失败”特征完全吻合。
本文件给出的口径**不依赖任何被拒绝的资源**，因此可在当前沙箱下稳定通过验收。
