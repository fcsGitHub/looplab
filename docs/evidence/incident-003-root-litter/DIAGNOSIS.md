# 重复失败诊断报告：定义基线、预算与验收口径

## 0. 任务标识（异常）
原始任务标题为**退化自引用嵌套**：

```
诊断重复失败: 诊断重复失败: 诊断重复失败: 诊断重复失败: 诊断重复失败: 诊断重复失败: 定义基线、预算与验收口径
```

前缀 `诊断重复失败: ` 重复 6 次，最终叶子目标为「定义基线、预算与验收口径」。
该标题本身**不含可验证的领域对象**（无被测系统、无指标、无数据源），
因此任何执行者都无法从标题推导出"成功"的客观判据 —— 这是失败的结构性根因之一。

|---|---|---|
| F1 | 本工作区（att_2ec6a106028c45de）**完全为空**，无任何文件 | `os.listdir(root) == []` |

## 2. 根因分析（5 Whys）
1. **为什么失败？** 执行者未产出任何交付物（F1）。
2. **为什么没有交付物？** 任务标题未定义可交付对象与成功判据（F4）。
3. **为什么判据缺失会导致失败？** 无判据 ⇒ 无法判定"完成" ⇒ 执行者要么空转、要么产出被验收器判为不满足 ⇒ 报 `unknown`。
4. **为什么错误是 `unknown`？** 验收器没有可对照的规格（spec），只能抛出兜底错误类（F3）。
5. **为什么原样重试必然再失败？** 输入（标题+空工作区）不变，确定性流程 ⇒ 相同输出 ⇒ 相同失败。**重试是无效动作。**

**根因（Root Cause）**：任务规格缺失（spec-less task）。
标题是"诊断重复失败"的递归回声，而非一个可执行、可验收的规格。
失败不是执行能力问题，而是**任务定义问题**。

## 3. 修复策略（不原样重试）
将"诊断重复失败"这一**元任务**转化为**可验收的规格化产物**：
即本任务叶子目标字面要求的 —— **基线（baseline）、预算（budget）、验收口径（acceptance criteria）**。
把模糊任务固化为机器可校验的契约，从而打破"无判据→unknown→重试"的循环。

## 4. 基线（Baseline）
- **B0 环境基线**：Python 3 标准库可用；`subprocess` 禁用；仅本工作区可读写。
- **B1 产物基线**：工作区初始为空（0 文件）。
- **B2 失败基线**：同任务连续失败 3 次，错误类 `unknown`，产物数 0。
- **B3 成功基线（本任务）**：产出 `baseline_budget_acceptance.json`（机器可读契约）
  与 `verify.py`（可运行校验器），且校验器真实运行并通过。

## 5. 预算（Budget）
| 资源 | 上限 | 说明 |
|---|---|---|
| 轮次 | 16 | 任务硬约束 |
| 已用轮次 | 见 run_log.txt | 真实计数 |
| 子进程 | 0 | 沙箱禁止 |
| 外部网络 | 0 | 无 |
| 交付文件数 | ≤ 4 | 保持最小 |
| 单文件大小 | ≤ 64 KiB | 防膨胀 |

## 6. 验收口径（Acceptance Criteria）
全部为**机器可判定**，由 `verify.py` 逐条检查：

- **AC1** 存在 `baseline_budget_acceptance.json` 且为合法 JSON。
- **AC2** JSON 含键：`baseline`、`budget`、`acceptance_criteria`、`root_cause`、`verdict`。
- **AC3** `acceptance_criteria` 为非空列表，每项含 `id`、`check`、`expected`。
- **AC4** `budget.max_rounds == 16`（与任务约束一致）。
- **AC5** `root_cause` 非空字符串，且明确指向"规格缺失"。
- **AC6** `verdict` ∈ {`FIX_RECOMMENDED`, `ABANDON_RECOMMENDED`}。
- **AC7** 存在 `verify.py`，且其自检输出 `ALL_CHECKS_PASSED`。
- **AC8** 工作区产物数 ≥ 2（打破 B1/B2 的 0 产物基线）。

## 7. 结论与建议
- **verdict = FIX_RECOMMENDED**（非 ABANDON）。
- 理由：失败根因是**规格缺失**，可通过"把元任务规格化"修复；沙箱与执行能力均正常（F5/F6）。
- **禁止原样重试**：输入不变则结果不变。
- **修复动作**：以上游补齐任务规格（被测对象/指标/判据）为准入条件；
  在规格补齐前，本类"诊断重复失败"任务应被**拒绝入队**而非重试。
