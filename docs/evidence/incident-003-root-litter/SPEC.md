# 基线 / 预算 / 验收口径 规格（实例化交付物）

> 本文件把任务 `定义基线、预算与验收口径` 实例化为可机检规格。
> 所有阈值均以 `spec.json` 为唯一真源，`verify.py` 读取并校验。

## A. 基线（Baseline）
- **B1 基线定义**：以“上一稳定版本”为基线，用固定随机种子 `seed=20240101` 复现。
- **B2 基线指标**：`pass_rate`（通过率）、`p95_latency_ms`（P95 延迟）、`cost_usd`（成本）。
- **B3 基线冻结**：基线值一经记录不得修改；变更须走新版本号。
- **B4 可比性**：候选与基线必须使用同一套实例、同一 seed、同一评测器版本。

## B. 预算（Budget）
- **G1 轮次预算**：单次尝试 ≤ `16` 轮（本任务约束）。
- **G2 时间预算**：单次尝试墙钟 ≤ `1800` 秒。
- **G3 成本预算**：单次尝试 ≤ `2.00` USD。
- **G4 超预算行为**：任一预算耗尽即 **中止并标记 `BUDGET_EXCEEDED`**，不得静默继续。

## C. 验收口径（Acceptance Criteria）
- **A1 正确性**：`pass_rate >= 0.90`。
- **A2 不劣化**：`p95_latency_ms <= baseline.p95_latency_ms * 1.20`。
- **A3 成本约束**：`cost_usd <= baseline.cost_usd * 1.10`。
- **A4 证据完备**：必须存在可复现的运行记录（命令 + 输出 + 版本）。
- **A5 判定规则**：A1–A4 **全部满足** 才判 `ACCEPT`；否则 `REJECT` 并给出失败项。
- **A6 不可判定**：若缺少基线或证据，判 `UNDETERMINED`（禁止默认通过）。

## D. 反模式（本次失败的教训）
- 禁止把“失败标签”当作“任务主题”递归喂入。
- 禁止无产物结束（会导致 `unknown`）。
- 禁止原样重试：重试必须改变输入或补充锚点。
